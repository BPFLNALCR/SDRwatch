# GUI Diagnostic Capture

Use this workflow when SDRwatch detection quality needs investigation: false positives, false negatives, wrong bandwidth, wrong center frequency, merged signals, split signals, or unstable baseline behavior.

The normal operator workflow is the web dashboard. The scanner CLI is an internal backend entrypoint invoked by the controller.

## Capture Workflow

1. Open the SDRwatch web dashboard.
2. Go to the Control page.
3. Select or create the monitoring location.
4. Enable the monitoring zones that cover the affected frequency range.
5. Turn on **Diagnostics mode**.
6. Start monitoring from the web page.
7. Reproduce or observe the detection problem.
8. Use **Export diagnostic bundle** for the active or most recent job.
9. Open the downloaded zip and fill in `NOTES.md`.

## Bundle Contents

The bundle is local and offline. When available, it includes:

- Job metadata and controller parameters
- Scanner command generated by the controller
- Scanner log tail
- Diagnostic JSONL tail
- Active baseline metadata
- Recent `baseline_detections` rows
- Recent `scan_updates` rows
- Enabled monitoring zones
- Known or friendly signals
- `NOTES.md` for operator observations
- `manifest.json` describing included, missing, and truncated evidence

Large logs and diagnostic JSONL files are bounded by default. Check `manifest.json` to see which limits were applied.

## Notes Template

Fill in `NOTES.md` before sharing the bundle for analysis:

- Expected behavior
- Actual behavior
- Frequency or band affected
- Problem type
- Additional notes

Problem type choices are false positive, false negative, wrong bandwidth, wrong center, merged signals, split signals, unstable baseline, and other.
